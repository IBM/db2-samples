# Trust Procedure Demo — Quick Start

These are samples, and are provided "as is" without any warranty of any kind.
They are meant for education purposes and not for production usage.  

There are 5 pieces that make up these samples.  One part is at the server, and the other 4 are at the client.

1) The server side trust procedure, which validates the app token generated by the clients to determine trust.
2) A CLI based application which includes the app token generation as part of the application
3) A shared library that contains the app token generation, which is "injected" into another application, in the example here it is loaded into the Db2 CLP process.
4) A Java based application which includes the app token generation as part of the application
5) A Java jar file that contains the app token generation, which is "injected" into another java application, in the example here it is loaded into a simple Java app.

Demonstrates Db2 trusted connections using an apptoken callback with
RS256 (RSA-2048 / SHA-256) digital signature and a 60-second expiry.

Requires Db2 12.1+ with a database, SECADM authority, and a TCP/IP listener.

Substitute your own values for the variables used throughout:

| Variable | Example | Meaning |
|----------|---------|---------|
| `$DB2DIR` | `/home/db2inst1/sqllib` | Db2 install / instance home |
| `$DB` | `testdb` | Database name (IPC connect) |
| `$TCPDB` | `testloc` | Database alias for TCP/IP connect |
| `$HOST` | `localhost` | Hostname for TCP/IP connect |
| `$PORT` | `60006` | TCP/IP port |
| `$AUTHID` | `boss` | Authid for the trusted context |
| `$PASSWORD` | `...` | Password for `$AUTHID` |
| `$DB2JCC` | `$DB2DIR/java/db2jcc4.jar` | JDBC driver jar |

If you change AUTHID then you also need to modify the trusted context user in src/server/setup.sql.

## Repository Layout

```
src/
  client/
    c/
      utilapptokensigner.h      Shared signing API header
      utilapptokensigner.c      Shared signing implementation (token building, key loading)
      demolibapptokengen.c      C shared library — generates signed apptokens (injected; no app changes)
      demoembeddedconnect.c     C demo app — inline callback via SQL_ATTR_APP_TOKEN_GEN_FUNC
    java/
      UtilAppTokenSigner.java   Shared signing utility (token building, key loading)
      DemoCallbackGen.java      Standalone Java token generator (democallbackgen.jar)
      DemoEmbeddedConnect.java  Self-contained Java demo app (inline callback)
      DemoSimpleConnect.java    Plain JDBC app (zero apptoken knowledge)
      stubs/                    Compile-time stub for DB2AppTokenGen (never deployed)
  server/
    trust_proc.sqc              Trust procedure source (embedded SQL + OpenSSL)
    setup.sql                   DDL: procedure + trusted context
test/
  c/
    test_apptokengen.c          C unit tests (no database required)
  java/
    TestTokenGen.java           Java unit tests (no database required)
build/                          All compiled output (created automatically)
Makefile                        Convenience wrapper — use instead of invoking bldapp/bldrtn directly
```

All C and Java build output is written to `build/` automatically.  The `build/`
directory is created on first use and can be safely deleted with `make clean`.

## Token Format

All token fields are concatenated with no separators or padding:

| Field   | Size     | Description |
|---------|----------|-------------|
| PREFIX  | 13 bytes | ASCII literal `TRUSTCALLBACK` |
| NONCE   | N bytes  | Raw nonce bytes supplied by the server |
| EXPIRY  | 8 bytes  | Big-endian `int64` — Unix epoch seconds (now + 60) |
| SIGLEN  | 2 bytes  | Big-endian `uint16` — byte length of SIG (always 256 for RSA-2048) |
| SIG     | 256 bytes| RSA-2048/SHA-256 signature over `PREFIX ‖ NONCE ‖ EXPIRY` |

The trust procedure verifies: prefix matches, `EXPIRY > now`, signature valid.

## 0 — Generate the key pair

Run once.  The private key is used by the client-side token generators
(C library and Java classes).  The public key is used by the trust procedure
on the server.

```sh
mkdir -p $HOME/trustproc_keys
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 \
    -out $HOME/trustproc_keys/private.pem
openssl rsa -pubout -in $HOME/trustproc_keys/private.pem \
    -out $HOME/trustproc_keys/public.pem
chmod 600 $HOME/trustproc_keys/private.pem
```

Both files must be present on every host where the client or the server runs:
- Client hosts: `private.pem` (keep confidential)
- Server (Db2 instance home): `public.pem`

## 1 — Build the trust procedure (`src/server/trust_proc.sqc`)

Precompiles, compiles, and installs the shared library to
`$DB2PATH/function/unfenced/` (required for `NOT FENCED` routines).

```sh
make trust_proc DB=$DB
```

> **Note:** `make trust_proc` calls `bldrtn`, which automatically calls `embprep`
> to precompile the `.sqc` file before compiling and installing the shared library.

---

## 2 — Set up the database objects (`src/server/setup.sql`)

Connect as a user with SECADM authority and run:

```sh
db2 connect to $DB
db2 -tvf src/server/setup.sql
db2 connect reset
```

This registers `DEMO.TRUST_PROC`, grants EXECUTE to PUBLIC, and creates
trusted context `DEMO_TRUSTCTX` for `$AUTHID`.

---

## 3 — Build and install the C apptoken library (`src/client/c/demolibapptokengen.c`)

```sh
make apptoken_lib
```

The built shared library is placed in `build/`.  Install it to all paths
searched by the Db2 client runtime:

```sh
for dir in \
    $DB2DIR/security64/apptoken \
    $DB2DIR/security64/apptokengen \
    $DB2DIR/security64/plugin/apptoken \
    $DB2DIR/security64/plugin/apptokengen; do
    mkdir -p "$dir"
    cp build/demolibapptokengen "$dir/apptokengen.so"
    chmod 755 "$dir/apptokengen.so"
done
```

Enable the library for TCP/IP connections:

```sh
# For the CLP (db2 connect) — must use db2cli writecfg, which writes to db2dsdriver.cfg:
db2cli writecfg add -parameter "APPTOKENGEN=ON"

# For CLI-based applications  — uses db2cli.ini:
db2 UPDATE CLI CFG FOR SECTION $TCPDB USING APPTOKENGEN ON
```

> **Note:** `db2cli.ini` is only read by CLI-based applications.  The CLP is an
> embedded application and only reads certain parameters from `db2dsdriver.cfg`;
> use `db2cli writecfg` to set `APPTOKENGEN=ON` there.  If you need both the
> CLP and CLI applications to use the apptoken library, run both commands.

**Verify with CLP:**

```sh
db2 connect to $TCPDB user $AUTHID using $PASSWORD
db2 "VALUES TRUSTED_CONTEXT"
# Expected: DEMO_TRUSTCTX
db2 connect reset
```

## 4 — Build and run the C embedded-callback demo (`src/client/c/demoembeddedconnect.c`)

The token generator is a function inside the application, registered directly
with the CLI driver via `SQLSetConnectAttr(SQL_ATTR_APP_TOKEN_GEN_CALLBACK, ...)`.
No `.so` installation or `APPTOKENGEN=ON` config required.

> **Note:** If you followed Step 3 and set `APPTOKENGEN=ON` for `$TCPDB`, the
> injected library will take precedence over the inline callback.  Disable it
> for the alias before running this demo, then re-enable it afterwards:
> ```sh
> db2 UPDATE CLI CFG FOR SECTION $TCPDB USING APPTOKENGEN OFF
> # … run demoembeddedconnect …
> db2 UPDATE CLI CFG FOR SECTION $TCPDB USING APPTOKENGEN ON
> ```

```sh
make demoembeddedconnect

./build/demoembeddedconnect $TCPDB $AUTHID $PASSWORD
# Expected: SUCCESS: Trusted connection established under context: DEMO_TRUSTCTX
```

## 5 — Build and run the self-contained Java demo (`src/client/java/DemoEmbeddedConnect.java`)

```sh
make java_embedded DB2JCC=$DB2JCC

java -cp build:$DB2JCC DemoEmbeddedConnect \
    "jdbc:db2://$HOST:$PORT/$TCPDB" $AUTHID $PASSWORD
# Expected: SUCCESS: Trusted connection established under context: DEMO_TRUSTCTX
```

---

## 6 — Build and run the zero-source-change Java demo

This separates the token generator (`democallbackgen.jar`) from the
connecting application (`DemoSimpleConnect`), mirroring the C approach.

**Build:**

```sh
make democallbackgen java_simple DB2JCC=$DB2JCC
```

**Run — trusted (appTokenGenClassName in URL):**

```sh
java -cp build:$DB2JCC:build/democallbackgen.jar DemoSimpleConnect \
    "jdbc:db2://$HOST:$PORT/$TCPDB:appTokenGenClassName=DemoCallbackGen;" \
    $AUTHID $PASSWORD
# Expected: SUCCESS: Trusted connection established under context: DEMO_TRUSTCTX
```

**Run — baseline (no parameter, should be NOT TRUSTED):**

```sh
java -cp build:$DB2JCC:build/democallbackgen.jar DemoSimpleConnect \
    "jdbc:db2://$HOST:$PORT/$TCPDB" \
    $AUTHID $PASSWORD
# Expected: NOT TRUSTED: TRUSTED_CONTEXT = NULL
```

## Integration tests (live database required)

Requires Steps 0–6 to be complete.  Runs each demo app as a subprocess
and checks its output:

| Test | App invoked | Expected result |
|------|-------------|-----------------|
| IT1 | CLP `connect to $TCPDB` via `demolibapptokengen.so` | `DEMO_TRUSTCTX` |
| IT2 | CLP `connect to $DB` (IPC — trust procedure bypassed) | `NULL` |
| IT3 | `./build/demoembeddedconnect` | `DEMO_TRUSTCTX` |
| IT4 | `java DemoEmbeddedConnect` | `DEMO_TRUSTCTX` |
| IT5 | `java DemoSimpleConnect` with `appTokenGenClassName` in URL | `DEMO_TRUSTCTX` |
| IT6 | `java DemoSimpleConnect` plain URL | `NULL` |

```sh
make integration_test \
    HOST=$HOST PORT=$PORT TCPDB=$TCPDB DB=$DB \
    AUTHID=$AUTHID PASSWORD=$PASSWORD
```

## Notes

- The trust procedure fires on **TCP/IP connects only** — IPC (`db2 connect to $DB`) bypasses it by design.
- Logs are written to `/tmp/trust_proc.log` (server), `/tmp/demolibapptokengen.log` (C library), and `/tmp/demoembeddedconnect.log` (C demo app).
- `NOT FENCED` routines load from `$DB2DIR/function/unfenced/` — `bldrtn -u` in Step 1 installs there automatically.
- The `src/client/java/stubs/` directory is compile-time only. Never include stub `.class` files on the runtime classpath.
- Keys are stored in `$HOME/trustproc_keys/`.  The private key must be readable only by the connecting user (`chmod 600`).  The public key must be readable by the Db2 instance user that runs the trust procedure.
- The trust procedure links against OpenSSL at runtime.  Ensure `libssl` and `libcrypto` are installed on the Db2 server (`openssl-libs` on RHEL/CentOS).
- Token expiry is 60 seconds from generation time.  Clock skew between the client and server host should be less than 60 seconds (NTP-synchronised hosts are fine).
- `bldrtn` and `bldapp` support both Linux and AIX.  On AIX, `xlc_r` is selected automatically; bitwidth is detected via `bootinfo -K`.
- OpenSSL must be installed on the build host.  On RHEL/CentOS: `openssl-devel`; on AIX: the OpenSSL fileset from the AIX toolbox.
- The `build/` directory is created automatically.  Run `make clean` to remove it for a fresh rebuild.
- `DB2JCC` defaults to `$(DB2DIR)/java/db2jcc4.jar`.  Override on the command line if your jar is elsewhere: `make java_unit_test DB2JCC=/path/to/db2jcc4.jar`.
